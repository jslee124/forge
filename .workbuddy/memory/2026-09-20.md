## 梳理 Forge 的上下文管理与压缩实现

用户询问项目如何管理上下文 / 如何实现上下文压缩。只读调研，未改代码。

上下文相关代码位置（供后续快速定位）：

- `docs/CONTEXT_MANAGEMENT.md`：权威设计+落地状态说明（属 catalog 的 currentProduct）。
- `packages/core/src/context.ts`：能力契约 `ModelContextCapabilities`、`budgetModelRequest`、
  `selectRecentConversation`、保守估算（UTF-8 字节 / 3 + 4，未知模型 32k 窗口回退）。
- `packages/core/src/runtime.ts`：`context.*` 事件族、adapter `projectContinuation` 集成、
  一次性 overflow 恢复、`limit_reached` 终态。
- `packages/core/src/cache.ts`：稳定前缀 hash 观测（`observePromptPrefix`），
  `checkpointGeneration` 是使其失效的因素之一。
- `packages/persistence/src/session-store.ts`：`previewSessionCompaction`、
  `createForgeSummaryCheckpoint`（确定性抽取式摘要）、`isCheckpointValid`、`extractiveSummary`。
- `packages/application/src/run.ts` `deriveActiveConversation`：校验 checkpoint 后拼
  `<conversation_memory authority="untrusted">` 进 instructions。
- `packages/application/src/codex.ts`：Codex 引擎也用同一 checkpoint 的有界视图包装 JSON。
- `packages/config/src/loader.ts`：项目配置只能更严格（mode 取更强、budget 取更小）。

关键行为：checkpoint 在 `recordRunInSession` 中一旦 history 增长即被丢弃，因此自动模式
（`prepareRun`）在压力超阈值且 checkpoint 失效时每轮重新压缩；低回收量会置 `paused`。

`apps/desktop/qa/` = D 阶段验收证据；`apps/desktop/dNN-qa.md` = 对应验收报告；
`dNN` 编号来自 `docs/DESKTOP_APP_TASKS.md`。
