# Forge Desktop 产品化 PRD

[English](../../development/DESKTOP_PRODUCT_PRD.md) · [实现方案](DESKTOP_PRODUCT_IMPLEMENTATION.md) · [路线图](ROADMAP.md) · [文档目录](../README.md)

更新：2026-10-26。状态：开发合同，正在分批实现。本文中的“v1”指本轮产品化范围，
不指定发布版本，也不代表功能已经实现。当前行为仍以源码、测试和正式验收记录为准。

## 1. 产品定位与目标

Forge Desktop v1 面向使用已有本地仓库的开发者，帮助其理解项目、完成一个边界明确的
小改动、运行验证，并检查结果。核心承诺是：用户能够知道 Agent 正在做什么、何时需要
自己决定、实际改变了什么、验证了什么，以及中断后如何继续。

这是一项从“可观察的 Agent 工程工具”走向“可独立完成开发任务的桌面产品”的拟议调整。
现行[产品定义](../product/concepts/PRODUCT.md)继续描述当前产品；本文不追溯改写它。

主要用户具备读取代码、检查 diff 和判断命令风险的能力；v1 不定位为无需开发知识的
全自动应用生成器。首次使用不要求用户理解 core、IPC、canonical history 或 token chunk。

## 2. 问题与证据边界

2026-10-25 在 macOS Electron 开发窗口实际走过审批、活动展开、运行终止、同会话恢复、
回答完成及活动回看。观察到：

| 观察 | 用户后果 | 责任范围 |
| --- | --- | --- |
| 审批重复显示命令预览和 JSON | 难以抓住动作、对象与授权范围 | 应用协议、Desktop |
| 接管期间批准了 8 项只读 grep/sed 查询 | 常规调查需要用户持续照看 | 工具接口、模型行为、权限策略 |
| 活动显示大量片段，计数停在 200 | 不知道实际执行了几项操作；展开挤走审批 | 事件投影、Desktop |
| 达到模型步骤上限，未交付建议 | 调查没有收敛到可用结果 | runtime、任务策略 |
| 内部英文运行说明以回答形式出现 | 无法区分答案与系统状态 | 历史投影、错误呈现 |
| 手写“基于已有信息直接回答”后恢复 | 恢复依赖用户知道如何提示模型 | 应用编排、Desktop |
| 完成反馈弱；活动条目展开后仅为句点 | 难以判断结束与回查过程 | Desktop、语义聚合 |

这是一次开发窗口的定性观察，不是整体成功率、已安装版本、Windows 或发布质量证据。
源码核对入口见[实现方案](DESKTOP_PRODUCT_IMPLEMENTATION.md#2-当前源码基线)。
旧桌面方案中的自动化验收不能代替本轮真实产品验收。

## 3. 范围与非目标

### 3.1 v1 必须覆盖

1. 在一个已选择的仓库中提问、调查和解释代码。
2. 完成范围明确的文件修改，并展示实际 diff 与验证结果。
3. 连续审批、运行进度、停止、拒绝、模型错误、预算耗尽及显式恢复。
4. 长回答、长工具输出、消息操作、运行活动回看与应用重开后的历史阅读。
5. 一条经过固定任务验证的原生引擎与模型组合，作为首条完整验收路径。
6. 中文与英文、明暗主题、键盘、中文输入法、桌面宽屏与窄窗口。

已有 Codex、模型设置、插件和研究能力保持可访问；它们的能力与验收范围分别说明。
v1 不默认展示所有高级控件；不删除已有兼容行为，也不宣称不同引擎完全等价。
首轮真实人工验收以 macOS 为起点；声称支持 Windows 产品发布之前必须补齐对应验收。

### 3.2 非目标

- 自主提交、推送、发布、部署或安装第三方依赖；仍需既有明确授权。
- 多 Agent 调度、云端协作、后台常驻任务、跨机同步或新的通用插件市场。
- 为重构而更换 runtime 框架，或为本轮强行引入新数据库、新公共 package。
- 自动恢复未完成的工具副作用、审批、进程或 provider continuation。
- 基于进程名称自动放行命令；v1 审批继续以“允许一次／拒绝”为核心。
- 把工作区策略或 `shell: false` 描述成操作系统隔离。

## 4. 核心用户流程

### 4.1 理解项目

选择仓库 → 输入问题 → 显示正在读取／检索的对象 → 得到有依据的解释 → 复制或继续提问。
常规专用读取不要求进程审批。信息不足时说明缺口；不能为了回答简单问题无界调查。

### 4.2 完成一个小改动

输入目标 → 必要的范围确认 → 调查 → 对需要确认的动作审批 → 编辑 → 验证 → 交付摘要与 diff。
交付必须区分实际改动、运行过的命令、命令结果与没有验证的事项。不能把模型停止输出
等同于用户目标已经完成，也不能把工作区内其他来源的修改归因给 Forge。

### 4.3 审批与拒绝

等待确认时立即显示稳定的审批区域：动作摘要、对象／目录、实际授权范围、完整命令入口。
默认聚焦拒绝；Tab 可到“允许一次”，确认后保留决定记录。长详情不推走操作按钮。
拒绝不自动结束整个任务：Agent 收到拒绝结果后可寻找允许的替代方案，且不得换写法重试
同一被拒绝动作。确实无法继续时说明原因。

### 4.4 失败与恢复

显示明确原因、已完成工作、未完成工作与可用恢复动作。恢复不是隐式重放：用户选择后
建立关联的新 run，重新加载当前配置、检查工作区状态并进行新的权限判断。
“基于已有信息总结”不调用工具；“继续处理”可能再次请求审批；“编辑重试”先恢复可编辑草稿。

## 5. 产品要求与验收标准

以下 R 编号是实现、测试与验收的追踪标识。

| 编号 | 要求 | 可验收行为 |
| --- | --- | --- |
| R01 | 清楚进入任务 | 仓库、有效模型与权限可查；配置错误在工具执行前给出可操作说明，输入保留 |
| R02 | 稳定运行状态 | 区分准备、模型响应、工具执行、等待审批、整理结果、结束；只显示有证据的阶段 |
| R03 | 可判断的审批 | 展示动作、对象、目录、范围；命令可完整查看；JSON 默认收起；允许一次和拒绝层级明确 |
| R04 | 正确审批生命周期 | 身份绑定到 run/action；重复、过期、取消后的决定被拒绝；连续请求有各自记录 |
| R05 | 可读的活动 | 一次工具调用一项；思考按连续片段聚合；计数不是 token chunk 数；截断与缺失可见 |
| R06 | 高效调查工具 | 支持按行读取和带上下文搜索，避免为普通局部读取而调用进程；边界与输出限制保留 |
| R07 | 受控收敛 | 遵守显式限额并在其中保留整理机会；停止有依据的无进展循环，不设默认总次数上限 |
| R08 | 原因明确的结束 | 保留成功、取消、拒绝终止、步骤／工具／上下文上限、模型／工具／存储故障的区别 |
| R09 | 可操作恢复 | 总结、继续、编辑重试只在具备对应能力时可用；新 run 关联旧 run；没有暗中重复副作用 |
| R10 | 可用的对话区 | Enter 发送，Shift+Enter 换行；IME 不误发；已发送消息与后续草稿分开；失败可恢复原输入 |
| R11 | 可信交付 | 显示实际变更、命令及结果；验证未运行／失败／不可确认有明确标签；模型结论不充当执行证据 |
| R12 | 长内容与消息操作 | 在底部时跟随输出，上翻时不抢滚动，有回到最新；复制、查看本次活动、显式重试可发现 |
| R13 | 历史与异常退出 | 完成后可回看运行；异常退出后展示中断和未知副作用，不恢复审批或自动重跑 |
| R14 | 跨入口兼容与诚实能力 | CLI、网关及旧会话不退化；Codex 未提供的进度／预算显示未知或不适用 |
| R15 | 可访问与性能 | 键盘可到核心操作，焦点可见；阶段变化播报，不逐片段播报；减少动效；长流不产生逐片段 DOM 行 |

### 5.1 审批卡片信息层级

- 标题：例如“请求执行命令”；等待状态使用静态确认图标，不持续显示执行 spinner。
- 摘要：例如“查询 studio.css 中的布局样式”。摘要是辅助解释，不能替代真实命令或风险判断。
- 范围：目录、目标资源、仅允许本次；风险标记来自工具与策略，而非模型自述。
- 详情：完整命令及参数；原始协议数据放诊断入口，默认不占据正文。
- 底部：拒绝／允许一次。按钮相对输入区位置稳定，只有详情区域可以限高滚动。
- 决定后：折叠为已允许／已拒绝；执行成功与授权成功是两种不同状态。

### 5.2 活动与回答

主对话优先显示当前动作和紧凑运行摘要；侧面板显示同一份活动数据的详细视图。
provider 返回的思考内容标明来源并合并展示；不生成不存在的思考，不以其作为权限或进度证据。
活动、失败和回答都关联 run。上下文诊断与用户活动分区，避免英文内部字段占满默认视图。
完成后显示结束原因、用时、结果入口；未知成本或用量显示未知。

### 5.3 预算与恢复

普通原生任务默认不设模型步骤、工具调用总次数上限；显式数字限额仍是硬边界，
在其中预留无工具整理机会。保留取消、命令超时、上下文与输出边界、保守的无进展兜底；
普通测试失败本身不构成循环。不限总次数并不提供金额消费上限。

显式限额太小或模型不支持整理时，应说明限制并使用确定性执行事实摘要。
限额或无进展触发的总结仍标为部分结果，不能伪装任务成功；网络和上下文条件不允许
模型总结时，事实摘要仍应可用。继续处理前展示实际限额（含不限）和权限规则；
拒绝、取消与进程失联不能被总结请求解除。参见
[2026-10-28 实现及验证](DESKTOP_PRODUCT_IMPLEMENTATION.md#13-原生任务总次数上限改为可选2026-10-28)。

## 6. 视觉与交互约束

沿用现有低饱和深浅主题、字体、图标和设计变量；本轮优先补齐语义与交互，不全面换皮。
审批、运行、失败、完成使用同一组间距、字号和状态标记。
普通正文与技术详情有清晰层级；状态同时用文字和图标表达，不能只依赖颜色。
至少验收 1100×728 与 840px 宽窗口，打开工作台、侧栏收起、长模型名和长命令。
核对 200% 缩放、键盘焦点、中文选词、减少动效及阶段读屏播报。

## 7. 产品验证与衡量

这些是拟议发布门槛，不是现有成绩。M0 固定任务与评分规则后才开始基线测量；不得在看到
结果后更换失败样本或降低门槛。每条记录保存任务版本、代码 revision、引擎／模型、配置、
原始 trace 或明确缺失原因、屏幕记录、grader 与人工判断。

固定 24 个任务：6 个仓库解释、6 个小改动、6 个诊断与验证、6 个失败恢复。
每个任务预先定义输入、允许的副作用、必要检查与成功标准；“正确拒绝／保留工作”可以是
负向任务的成功结果。两轮独立运行分别报告，不能混合成一个更好看的分数。

| 指标 | 口径 | v1 门槛 |
| --- | --- | --- |
| 任务成功 | grader 与人工核对均满足标准的任务数／24 | 每轮至少 22／24；所有权限与恢复关键用例通过 |
| 无指导完成 | 5 位目标用户各做 3 个固定任务，无开发者提示完成数／15 | 至少 12／15；逐项保留失败原因 |
| 审批负担 | 每任务请求数、用户决定数及请求原因 | 专用工作区只读操作为 0 次审批；进程审批按实际策略，不设不安全的减量目标 |
| 重复调查 | 相同输入且资源版本未变的重复读取／搜索；单独报告有理由的重读 | 无无限重试；固定重复循环用例必能收敛或停下 |
| 延迟 | 首个有意义反馈、首个答案、总时长；审批等待另计 | 报告各任务与 p50/p95，对照基线；不得以跳过验证换取速度 |
| 故障恢复 | 原因可识别、已有工作保留、正确恢复的注入场景数／全部注入场景 | 所有确定性契约用例通过；无未授权重放 |
| 可读性与性能 | 10,000 个流式片段、长回答、长命令、500 项工具活动的固定压力场景 | 不生成 10,000 行活动；输入与停止可用，无隐藏截断 |

确定性测试通过、外部模型任务通过、用户试用、已安装应用和发布资产分别记录。
每个拟发布的系统与架构都要有对应安装和启动证据；macOS 开发窗口不能替代 Windows 证据。

## 9. 风险与取舍

- 模型、提示词与工具共同影响收敛；用相同任务分别比较，不能从一次失败认定模型或框架无效。
- 持久化增加本地敏感数据：只保存脱敏、有限输出；保持本地权限，不新增默认遥测。
- 收起诊断可能降低工程透明度：保留可发现的完整详情入口和明确截断标记。
- 预留总结会减少调查步骤：在固定总预算下评估交付率，并保留配置与回退方式。
- 运行期间允许浏览历史需要分离浏览会话和执行会话；v1 不允许借此启动第二个写入任务。
- 产品版本验收前不得把本文的拟实现能力写入 packaged product help。
