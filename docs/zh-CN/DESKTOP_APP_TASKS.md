## 执行规则

2026-09-06 创建。本文是 `current-development` 执行清单，设计合同是产品范围依据，
当前源码和测试是现有行为依据。所有任务初始为 **未开始**；文档完成不代表软件实现完成。
本次工作只编写清单，不启动实现、不安装依赖、不发布应用。

按依赖执行，每个任务保持可独立审查和回退。技术细节由执行 agent 核实并记录；
涉及改变已确定范围或增加外部成本时才请求新的决定。不要反复询问已确定的技术栈。
未经明确授权不发布、不上传文件、不使用付费 provider；可继续完成离线独立工作。
本文不要求启动多个 agent。

## D01 · 基线与技术验证

现有插件动态加载和资源定位。确定具体版本、进程 API、IPC 方式、macOS 最低版本与
芯片覆盖；打包工具和分发方案记录为明确选择。不要从 Codex 产品现状推断本地接入能力。

**验收**：每个技术选择有依据和验证步骤；未验证项目明确标记；无 agent loop 重写。
验证 react-diff-view 长文件、多文件、中文路径及大量修改样例后再锁定。
明确关闭窗口、退出应用、跨引擎续聊规则；不能默认具有后台运行或无损引擎切换能力。

**入口**：[run.ts](../../apps/cli/src/run.ts)、[TUI](../../apps/cli/src/interactive/app.tsx)、

**验证**：读取当前测试，选择最小离线基线；记录命令和结果，不搬用旧验收数字。

**完成记录（2026-09-06，Complete）**：基线、引擎路径、依赖矩阵、Electron 44.2.0

## D02 · Electron 工程与打包冒烟

**交付**：在现有 monorepo 增加桌面入口（建议 `apps/desktop`），使用已选 Electron、
React、TypeScript、electron-vite。配置主进程、preload、renderer 和最小 Agent 子进程入口，
保留共享包检查。桌面包保持 private；开发命令与现有 TUI 命令分开。

**验收**：窗口和子进程启动、通信、关闭可验证；renderer 不获得任意 Node/IPC 能力；
开发态与一个本地打包产物都能找到进程入口和必需资源。无须签名或发布即可先暴露打包问题。
**验证**：构建、类型检查、无网络的进程启动/退出冒烟，检查错误与监听清理。

**完成记录（2026-09-07，Complete）**：新增 private 的 `apps/desktop`，锁定
Electron 44.2.0、electron-vite 5.0.0、React 19.2.8，接入 TypeScript project
references、独立的根级 `desktop:*` 命令，以及 electron-builder 26.15.3 的
macOS 13+ arm64/x64 DMG/zip 配置。主进程持有一个 `utilityProcess`；最小 Agent
只接受校验过的 D02 健康检查/关闭消息，关闭会等待子进程退出并保留 kill 兜底。
renderer 启用 sandbox/context isolation、禁用 Node integration；preload 只暴露
一个固定健康检查方法，不暴露裸 IPC。Agent 与内置 Skill/docs 资源均位于 ASAR
之外。验证结果：2 个聚焦测试文件/5 个测试通过（非法消息、资源缺失/存在、通信、
异常退出、监听清理）；`CI=true pnpm check` 通过；最终 electron-vite 构建通过。
开发态隐藏窗口与本地未签名 arm64 `.app` 均实际加载 renderer、连通 Agent、找到
资源、完成关闭并以 0 退出。打包冒烟复用已安装 Electron 分发包，无须重复联网下载。
签名/公证、x64 实机执行、DMG/zip 产物生成及发布仍未验证并留给 D13；D02 只要求
一个本地打包产物，不代表这些 D13 结果已成立。

**验证**：实际截图检查中英文、长回复、表格代码、窄窗口、键盘焦点；记录截图和差异修正。

## D04 · 共享应用服务抽取

**交付**：从 CLI 抽取非呈现的配置、执行组装和会话操作为 private 共享服务。
尽量保留原类型与薄兼容入口，TUI 继续调用相同语义；包名在 D01 决定。

**验收**：不把 React/Ink 引入 core；两引擎认证边界、策略、Skills/插件及上下文语义不变；
不用终端字符串重建协议，不新增平行任务实体。为依赖注入保留离线 fake 能力。
**验证**：相关 CLI/session/provider 回归、`CI=true pnpm check`、跨层确定性评估。
回退该提取应不需要用户数据迁移。

**完成记录（2026-09-07，已完成）**：新增私有 `@forge/application`
（`packages/application`），承接原生执行组装、Codex 执行/认证/模型发现、adapter
选择、图片解析和持久会话/上下文操作；根入口也导出现有配置与指令加载函数。
CLI 原路径保留兼容导出与薄包装。终端事件渲染、审批预览/提问、SIGINT、浏览器打开
和终端超链接格式化留在 CLI，按需注入。共享服务不依赖 CLI、React、Ink 或 Electron，
不访问终端输入输出；保留原生 `RunEvent`/`RunResult`、现有 Codex 结构化输出、
adapter/client fake 注入、审批与取消。输出 sink 仍是兼容接口，不是桌面通信协议。
没有新增或迁移 agent loop、会话 schema、权限、provider 凭据、资源策略或任务实体。
D05 仍需定义并校验真实进程协议，并处理现有 Codex bridge 的能力限制。

验证：application/CLI/session/config/provider 定向回归 14 文件 / 91 项通过，
包含不依赖终端的执行/保存/重启恢复及应用层依赖边界测试；`CI=true pnpm check`、
`CI=true pnpm eval:deterministic`（13 文件 / 71 项）通过。工作区引用、锁文件链接、
打包及版本/tag manifest 列表均纳入新私有包；`CI=true pnpm package:verify`
打包安装验证通过（tarball 336,459 字节），另一次重试遇到 registry HTTP 503。
现有第三方锁定版本未改变。
桌面真实执行与真实 provider/认证检查留待 D05–D08，回退此次抽取不需要用户数据迁移。

## D05 · Agent 进程和通信协议

**交付**：主进程管理 Agent 生命周期，类型与运行时校验结合的请求/事件/审批/取消协议。
标识 request、Session、Run 和事件序号，定义订阅、完成、断开、重复/过期事件处理。
不把 AbortSignal 等进程内对象直接当可序列化协议；用关联的取消消息桥接。

**验收**：事件不串任务；拒绝未知操作与无效参数；只暴露必要桥接接口；渲染层不持有
凭据。Agent 崩溃结束等待并显示中断，不重放副作用。连续启动关闭无监听与进程泄漏。
**验证**：离线测试串线、重复/迟到消息、审批取消、断开与进程终止；进程隔离不称为沙箱。

## D06 · 工作空间与会话接入

**交付**：真实目录选择，复用 cwd/root 解析；未选目录在有效提交时创建
`$FORGE_HOME/workspaces/<id>/`。映射任务到 Session，接入创建、列出、恢复和草稿。
沿用 JSON/JSONL，展示实际 Forge home；实现最小占用拒绝或冲突检测，不加接管服务。

**验收**：Git 子目录和普通目录解析准确；恢复不改变工作空间边界或恢复授权；
损坏/缺失目录、配置覆盖、写入失败和并发冲突有反馈，旧 snapshot 不被破坏。
只访问自己的自动目录，不把 Forge home 整体开放。无强制 inputs/outputs 或 task.json。
**验证**：config、workspace、persistence 回归；临时目录测试重启恢复与覆盖保护。

## D07 · 原生 Forge 真实执行

**交付**：真实提交、流式文本、工具活动、审批、取消、结果保存和上下文显示。
显示状态由真实事件驱动；UI 不自行推断成功或伪造固定步骤。

**验收**：连续两轮，真实读取/修改/命令，拒绝动作不执行；取消后不派发新动作，
确认前显示停止中；完整工具交换可恢复，运行状态和验证结果区分。TUI 不退化。
**验证**：先 fake adapter 端到端，再在获准且已配置条件下做最小真实 provider 测试；
记录两类证据，缺真实凭据不阻止完成离线部分。

## D08 · Codex 执行与认证

**交付**：通过既有 Codex 执行与认证路径接入同一工作台，显示 engine/model，
提供不可用、未认证及依赖缺失反馈，不复制其他应用凭据或静默切换原生 Forge。

**验收**：启动、认证状态、输出、错误、取消和历史恢复分别验证；Forge 插件不冒充
Codex 工具；不能仅返回成功退出码就宣称审批和来源信息完整。若现有桥接缺少必需能力，
先列出差距并实现或明确受限，而非伪造 UI。运行中禁切引擎，续聊遵循 D01 的规则。
**验证**：现有 Codex transport/CLI 离线测试与已授权的本地集成分开报告。

## D09 · 文件操作与差异审查

**交付**：工作空间文件打开、预览、另存为；外部文件显式添加副本及同名处理；
单次审批 diff 与累计审查分开。定义比较基线，普通目录有可检查的变更记录。

**验收**：用户预存改动不归因于 Agent；缺证据时标明比较范围，尤其 Codex 路径。
取消导出不写文件，覆盖需明确选择；原文件和历史引用保留。外部材料不扩大源目录权限。
**验证**：新增、修改、删除、同名、符号链接越界、外部并发修改、两种引擎的变更归属。
不要为了全面追踪复制整个项目。

## D10 · 内容读取与文档预览

**交付**：共享有界读取接口；PDF.js 按页文字与预览，Papa Parse CSV/TSV 读写，
文本与图片预览。解析由执行侧可复用，renderer 不直接获得任意文件读取能力。
为模型提供有界访问方式，不只做用户可见预览；两引擎可用范围分别说明。

**验收**：来源、页码/行范围、错误、截断可见；无文字 PDF 不声称 OCR；CSV 前导零
保留，分析使用实际计算，预览范围与分析范围区分。DOCX/XLSX 不作为首版门槛。
**验证**：中文/多栏/无文字 PDF，worker/字体打包；引号/换行 CSV、TSV、错误行、
部分预览、全量计算；大文件有边界且可取消。

## D11 · 搜索插件与来源报告

**交付**：复用 web-tools，设置里显式安装/启用/配置，保留 Brave/DuckDuckGo；
既有受控 HTTP 请求后使用 Readability + jsdom，无脚本、无解析器自行联网。
添加基本提取回退、来源记录和 Markdown 报告。

**验收**：服务选择明确，auto 不等于失败后切换；保留逐次网络审批，TUI 默认插件集合
不变。区分搜索摘要、正文、截断和失败，关键事实关联实际来源。Codex 研究能力单独核实，
没有来源字段时不能伪造。新插件分发机制须兼顾已有插件路径与资源打包。
**验证**：现有 web-tools 回归，加文章/列表/脚本依赖/失败/重定向/输出限制测试；
获准后做真实服务检查。结果质量与离线解析分别报告。

## D12 · 全流程与故障验收

**交付**：三条完整流程与双引擎能力矩阵，缺口、风险与当前证据。
每条流程明确在哪个引擎验收；产品支持两引擎不代表所有能力完全相同。

**验收**：代码修改与审查、本地文件生成与预览、带来源研究都走通；中英文覆盖。
故障覆盖崩溃、取消、目录丢失、存储失败、网络不可用、历史损坏、冲突与未配置模型。
没有真实证据的单元格标记未验证，不用 mock 覆盖真实支持声明。
**验证**：`CI=true pnpm check`、`CI=true pnpm eval:deterministic`、聚焦回归与实际 UI 检查。
资源/公开制品改变时加 `CI=true pnpm package:verify`。列出未运行的检查及原因。

## D13 · macOS 安装包与交接

**验证**：本机安装冒烟和已选架构检查；签名、公证、更新、发布均独立记录。
缺少签名或发布授权时交付可审查的本地产物与剩余步骤，不擅自发布或宣称正式交付。
