## 1. 产品目标与范围

Forge 是兼顾代码项目和日常工作的桌面 AI 助手。清晰、易用的 UI 与协作体验是目标，
不要求第一版替代成熟产品或成为用户每天优先打开的应用。

第一版走通三条流程，共享同一工作台，不要求用户先选择任务模式：

| 流程 | 端到端体验 | 成果 |
| --- | --- | --- |
| 代码修改 | 打开文件夹 → 描述需求 → 修改与验证 → 审查差异 | 实际代码文件、差异、验证结果 |
| 本地文件与文档 | 添加文件或文件夹 → 阅读、整理或生成 → 预览并打开 | 工作目录中的实际文件 |
| 资料研究 | 问题或链接 → 查找与分析 → 带来源的报告 | 报告文件、可核查的来源 |

三条流程是产品方向；首批格式、研究范围和搜索接入方案见第 5 节，具体依赖及真实服务表现尚待核实。能力不支持时应明确提示，
不能只展示模拟成功。邮件、日历、云盘、插件市场、云端执行、跨设备同步、后台常驻、
多任务并行编排和 TUI/桌面运行接管不属于本合同的首版交付要求。

## 2. 当前源码事实

| 事实 | 代码依据 | 桌面含义 |

| TUI 提交通过事件、取消和审批接口调用执行层 | [interactive/app.tsx](../../apps/cli/src/interactive/app.tsx) | 桌面消费结构化接口，不解析终端文本 |

| Session 存于 Forge home 的 `sessions/`，运行 trace 存于 `runs/` | [session-store.ts](../../packages/persistence/src/session-store.ts)、[trace-store.ts](../../packages/persistence/src/trace-store.ts) | 复用持久化与恢复合约 |
| 内置工具是列表、读取、搜索、编辑和命令执行 | [registry.ts](../../packages/tools/src/registry.ts) | 通用文档预览与研究能力需另行补齐 |

TUI 两条路径；桌面首版已确定同时支持这两种引擎，不将一条引擎的能力或事件冒充另一条。

## 3. 工作目录与数据模型：已确定

### 3.1 概念映射

- 工作空间：真实文件夹；Git 仓库和普通文件夹都有效。
- 界面任务：现有 Session，一段可以持续的对话。
- 一次发送：在 Session 中创建一个有界 Run。
- 成果：真实工作文件；会话记录引用文件，不托管另一套成果副本。

不增加与 Session 平行的任务执行实体，不强制创建 `task.json`、`inputs/` 或 `outputs/`。
名称、最近访问、收藏等导航元数据如确有需要，以最小扩展设计，不能复制规范会话历史。

### 3.2 目录规则

| 场景 | 行为 |
| --- | --- |
| TUI | 保持现有 `cwd` 和 workspace root 解析 |
| 桌面打开文件夹 | 将选择的位置交给相同目录解析流程 |
| 项目内新建任务 | 沿用该工作空间及明确的工作目录 |
| 独立任务未选择文件夹 | 自动创建 `$FORGE_HOME/workspaces/<id>/` 作为普通工作目录 |
| 生成或修改文件 | 工具按现有路径语义直接写入工作空间；不强制成果子目录 |
| 另存为 | 导出副本到用户选定位置；原文件保留，历史引用不被静默改写 |

`FORGE_HOME` 默认为 `~/.forge`，桌面与 CLI 共用解析规则。桌面从系统启动时未必继承
终端环境变量；实施时核实并展示实际生效位置，不能假定两端总是读同一个自定义目录。
临时工作目录创建建议延迟到首次有效提交，避免仅打开首页就产生空目录。

例如在 `/projects/site/src` 开始工作，若上级 `/projects/site/.git` 存在，
则 `cwd=/projects/site/src`、`root=/projects/site`，`login.ts` 相对 cwd 解析。
界面不能暗示选择子目录就把访问范围限制在该子目录；必要时同时展示仓库范围。

已有配置、会话、trace 留在 Forge home，代码项目文件留在项目中。自动工作目录的边界
必须是该目录，不能把整个 Forge home 作为 workspace。核实此布局与现有保护规则兼容；
如冲突，应报告并修复窄边界，不得放宽内部配置、凭据或会话存储的访问权限。

### 3.3 会话与恢复

存储方案已于 2026-09-06 确定：第一版继续使用现有 **JSON 会话快照、JSONL 运行记录
和工作目录中的普通文件**，不引入数据库。桌面与 TUI 复用现有持久化实现、格式校验、
脱敏和原子保存行为；不得为桌面另建一套不兼容的会话存储。

复用 Session schema 和有序 Run 记录。新任务对应新会话；继续任务恢复历史后新建 Run。
恢复不能重放未完成工具、恢复子进程、provider continuation 或审批授权。
第一版不设计“停止并接管”的跨客户端协议，不宣称提供实时同步。
在共享存储上仍须避免并发覆盖：实施时选择最小的冲突检测或占用拒绝机制，
用清晰错误阻止覆盖即可，无需引入后台调度系统。

### 4.1 结构与消息

- 保留浅色、简洁、留白充分的方向；左侧项目/任务，中间对话，右侧可收起的成果预览。
- 用户与 Agent 均无头像，不保留头像占位列。
- 用户消息保持靠右的轻量气泡；Agent 正文直接排版在对话表面，无外层气泡、边框或卡片。
- 长回复自然延伸，使用标题、段落、列表和间距；不放进独立的小滚动框。
- 代码块、表格、审批内容可有必要的局部样式。正文保持可读行宽，不为占满空间而拉长。
- 详细命令输出按需展开；切换任务保留各自未发送草稿。
- 运行状态、失败与需要用户处理的事项清楚可见，不使用虚构进度百分比。

### 4.2 首页

新建任务进入简洁输入页，提供需求输入、添加文件、工作文件夹选择、模型选择和发送。
可用“修改代码 / 处理文件 / 研究问题”作可编辑示例，不作为强制运行模式。
全局新建可以不选文件夹；项目内新建显示已关联的目录。
文案“有什么需要一起完成？”是建议，不是已冻结的翻译词条。

### 4.3 工作台

顶部展示任务名称、实际工作位置和状态。输入区支持继续追问、材料、模型和停止。
右侧按内容展示文件、差异或报告，并支持打开文件、打开所在文件夹、另存为。
前端须区分正文、工具活动、审批请求和运行结果；工具失败与整个 Run 失败不是同义词。
展示实际正在发生的动作，不固定为“阅读 → 实现 → 验证”的线性步骤。
没有运行验证时不能展示“测试通过”；Run 完成也不能自动等同于用户目标已验证。

审批前的单次编辑预览与任务结束后的累计改动审查须分开。
后者仍需实现：Git 项目不能把用户预存改动全部归因于 Agent；普通文件夹也要有明确
审查方式或明确显示尚不能提供的比较范围。不能只展示最终文件就宣称完成差异审查。

### 4.4 设置与双语

首版完整支持简体中文和英文。语言入口仅位于设置中，不常驻侧栏、首页或输入区。
建议路径为“设置 → 通用 → 语言”，选项为“跟随系统 / 简体中文 / English”。

- 语言切换保留任务、草稿、附件和当前执行；不重新发起模型请求。
- 导航、按钮、空态、状态、错误、审批和辅助说明都使用翻译资源。
- 历史对话、文件、命令输出不因切换界面语言被自动翻译；界面语言不等同于回答语言。
- 两种语言使用同一布局，允许英文扩展与换行；不按中文文案宽度固定控件。
- 键盘操作、焦点和可访问名称覆盖两种语言；不能只用颜色说明运行状态。
- 界面设置由宿主存储，不能让项目配置改变用户界面语言。具体设置字段位置待实施确定。

## 5. 共享架构与能力边界

### 已确定的桌面进程分工

2026-09-06 确定采用独立 Agent 进程：

| 进程 | 职责 |
| --- | --- |
| React 渲染进程 | 对话、预览、设置界面与用户交互 |
| Electron 主进程 | 窗口生命周期、系统对话框、打开文件及受控通信转发 |
| Agent 进程 | 运行共享应用服务和现有 Forge 执行核心，处理任务、工具及运行事件 |

Agent 执行不放进渲染进程或窗口主进程。具体子进程 API、通信 transport 和进程数量
在实现方案中确定；此决定不引入后台常驻服务、多任务调度或跨端接管。
独立进程不是安全沙箱，现有策略、审批和工具边界仍须执行。
通信需要关联请求、Session 和 Run，明确错误、取消及断开行为；Agent 异常退出时
界面应显示中断并解除等待，不自动重放可能有副作用的操作。应用退出时应明确清理
其拥有的 Agent 进程，不能因窗口隐藏就假定执行已停止。

### 共享服务与接口

建议依赖方向：桌面 UI / TUI → 共享应用服务 → core、config、persistence、
model adapters、tools、resources、plugin host。

共享服务负责执行组装、会话操作、配置操作、事件订阅和取消/审批桥接。
优先抽取现有 CLI 非呈现逻辑，包名和 transport 尚未确定。保持 private 包约束。
Core 保留策略、上下文和执行决策；persistence 保留存储校验和迁移；adapter 保留认证与
provider 协议职责；UI 不绕过这些边界直接执行模型提议的文件或进程操作。

以现有 `RunEvent`、`RunResult`、审批描述为基础定义桌面协议，补充必要的标识和排序，
不要把 stdout 字符串作为协议。模型事件、显示历史和模型续聊历史不可相互混用。
若采用 IPC，参数须校验、事件须关联正确会话、关闭订阅须清理监听；渲染层不持有密钥。

文件材料不能只因拖入路径就扩大目录授权。现有 workspace 文件引用和显式图片附件
有不同语义，通用外部文档的导入、复制或窄读取授权需另行定义。预览外部 HTML 等内容
必须隔离执行能力，不能让成果内容获得应用权限。

研究依赖可用且经过现有策略的搜索/抓取能力；目前示例插件不等于默认内置支持。
内容解析选型见下节；具体版本、服务配置交互、来源数据结构和失败回退在能力阶段落实。
来源不可捏造，报告结论应关联实际读取的来源；不可把模型猜测包装成已查证事实。

### 已确定的首批文档与研究范围

2026-09-06 确定以下范围。支持必须区分读取、生成/修改与预览；具体大小、页数、行数
限制在实施时明确，超限与不支持的情况需可见，不能静默截断后声称处理了全部内容。

| 格式 | 首版能力 | 边界 |
| --- | --- | --- |
| Markdown、TXT | 读取、生成、修改、预览 | Markdown 是文档与研究报告的主要输出格式 |
| 代码、JSON、YAML 等文本 | 读取、修改、高亮、差异审查 | 沿用现有文件工具与路径规则 |
| PDF | 提取文字、按页预览、引用页码 | 先支持有文字层的文件；扫描件 OCR、直接编辑原 PDF 延后 |
| CSV、TSV | 读取、分析、生成、表格预览 | 明确文件大小与预览行数限制 |
| PNG、JPEG | 预览；按模型能力分析 | 不支持图片输入时明确提示，不伪造已看图 |
| DOCX、XLSX | 后续扩展 | 用户偶尔使用，首版不以此为验收前提；后续优先基础读取与简单生成 |

不承诺 DOCX/XLSX 复杂排版、公式、批注或修订的无损往返。
显式添加工作空间外的文件时，默认复制到当前工作文件夹，并明确显示是在添加副本；
处理同名冲突，不静默覆盖原文件。工作空间内已有文件直接引用，不重复复制。
添加副本不授予源文件所在文件夹的访问权限，不要求额外的 inputs/outputs 目录。
这是桌面通用添加文件流程；不改变现有 TUI 显式图片附件的行为。

研究首版覆盖公开网页搜索、用户链接读取和用户提供的本地材料，主要成果保存为带来源
的 Markdown 报告并在工作台预览。登录网站、浏览器自动操作、付费数据库和定时研究延后。

- 保存实际访问的 URL、标题、访问时间，以及可获得的发布时间；缺失时间不得捏造。
- 关键事实关联来源链接，本地 PDF 引用文件和页码。
- 只获得搜索摘要时标明读取程度，不能声称已阅读全文。
- 无法访问、需要登录、提取失败或内容不足时明确反馈，不生成虚构来源。
- 两种引擎共用报告展示，各自核实搜索/抓取能力；原生 Forge 的服务接入按下节实施，
  不因采用 Codex 引擎就默认具有相同工具或来源数据。

验收包含一份有文字层的多页 PDF、一份 CSV/TSV、一次公开网页研究，以及不支持格式、
扫描 PDF、外部文件同名冲突和网页读取失败的明确反馈；离线与联网证据分别记录。

### 已确定的搜索与网页读取实施方案

2026-09-06 确定复用 [web-tools 示例插件](../../examples/plugins/web-tools/index.mjs)
作为原生 Forge 的实现基础，继续通过插件机制扩展，不将特定搜索服务写入 core。
桌面设置提供明确的安装、启用与配置入口，避免要求用户手动复制插件目录；
不静默启用插件或改变 TUI 默认工具集合。插件来源、分发方式和配置存储须在实施时明确。

- 保留 Brave Search 与 DuckDuckGo HTML 两条现有路径，首版不增加更多供应商。
- 明确显示所选服务和实际请求服务；现有 auto 行为是存在 Brave Key 时选 Brave，
  否则使用 DuckDuckGo，不将此描述为请求失败后的自动切换。
- 先验证真实连通性、结果质量及失败反馈，再确定推荐服务；当前不承诺服务可用性。
- 复用地址、重定向、MIME、超时、下载和输出限制。完善正文提取，明确区分搜索摘要、
  实际正文和截断结果；记录请求 URL、最终 URL、访问时间、可获得的发布时间及阅读程度。
- 报告关键结论关联实际来源；读取失败说明原因，不捏造正文或引用。
- 首版沿用现有每次网络请求审批，桌面不能隐藏或绕过审批。
  “允许本次研究访问公开网页”等有范围、有时限的授权另行讨论，若实施必须由 core 决策。
- Codex 引擎不使用 Forge 插件；分别核实能力，不承诺工具、配置或来源字段完全相同。

| 能力 | 选型 | 实施边界 |
| --- | --- | --- |
| PDF 读取与页面预览 | PDF.js（pdfjs-dist） | Agent 侧按页提取，桌面侧渲染；提取结果保留页码 |
| CSV / TSV 解析与生成 | Papa Parse | 保留原始字符串，明确需要计算时才转换相关列 |
| 网页正文提取 | Mozilla Readability + jsdom | 解析现有受控请求取得的 HTML，不自行联网 |

PDF 按页、有界读取，不将全文默认注入模型上下文。文字提取不代表完整版式理解；
没有可提取文字的页面明确标记，不视为空白或声称已完成 OCR。首版不为此要求安装
Python 或系统 PDF 命令。验证打包后的 PDF worker、字体等实际所需资源能够加载。

CSV/TSV 保留如 `00123` 的编号，不默认启用自动类型转换。计算通过实际计算逻辑完成，
解析成功不代表分析正确。部分预览标明范围，分析范围与预览范围分开；报告解析错误，
不静默丢弃异常行。明确编码、分隔符、空值和数值转换规则。

网页使用现有 web_fetch 请求检查后取得 HTML，再交给 jsdom 和 Readability。
保持脚本执行和远程资源加载关闭，传入最终页面 URL 解析相对链接，不调用解析器的
自动联网入口。默认向模型和界面提供有界文本，不直接插入未经处理的 HTML。
Readability 提取失败或不适合列表/论坛页时，保留现有基础文本提取作为回退，注明
方式、读取程度和截断。需要 JavaScript 才能获得正文时明确反馈，不自动启动浏览器。

通过薄的共享内容读取接口返回来源路径或 URL、页码/行范围、正文、截断及错误信息。
解析器不负责授权；文件访问、网络审批与执行权限仍由 Forge 管理。保持该层可供
TUI 与桌面复用，不让桌面预览逻辑成为模型读取内容的唯一入口。

集成验收覆盖中文与多栏 PDF、无文字页面、带引号和字段内换行的 CSV、TSV、
前导零编号、部分预览与全量计算的区别、文章页、列表页、提取失败和回退。
这些是待完成的验收要求，不是已通过的兼容性证据。

参考：[PDF.js](https://mozilla.github.io/pdf.js/examples/)、
[Papa Parse](https://www.papaparse.com/docs)、
[Readability](https://github.com/mozilla/readability)。

## 6. 实施阶段与验收

### A. 设计和技术决策

桌面容器已于 2026-09-06 确定采用 **Electron**，不再把 Tauri 或原生界面作为待选容器。
实施前选择具体 Electron 版本，核实其内置 Node.js 与 Forge 当前 `node >=24` 要求、
现有依赖及打包后工具执行的兼容性；不能仅凭开发环境可运行就认定安装包可用。
桌面界面已于 2026-09-06 确定采用 **React + TypeScript**。复用类型和非界面逻辑，
桌面组件使用 Web UI 实现，不直接复用 Ink 终端组件。React 负责呈现与交互；
Agent、文件操作和认证继续留在执行层，遵守第 5 节的共享架构与权限边界。
首发平台已于 2026-09-06 确定为 **macOS**，第一版在 macOS 上完成支持与验收。
代码保持跨平台结构，平台专属行为集中在适配层；Windows 和 Linux 后续单独适配、
打包与验证，不因采用 Electron 就宣称已支持。macOS 最低版本及芯片架构覆盖在打包阶段明确。
构建与界面基础已于 2026-09-06 确定为 **electron-vite + Tailwind CSS + 按需引入 shadcn/ui**。
electron-vite 负责桌面开发与构建，不另行维护并行的 Electron Forge 构建链；安装包、
签名与分发工具仍待选择。保留 monorepo 共享包的 TypeScript 检查，明确主进程、preload、
渲染层及 Agent 进程的构建入口，并验证插件、资源和子进程入口在打包后可用。
Tailwind 配合统一的颜色、间距、圆角和字体设计变量；封装重复结构，避免逐页面分散定义。
shadcn/ui 按需用于菜单、对话框、提示和表单等基础组件，引入的组件代码由项目维护。
对话、执行活动、审批、成果预览和输入区按本文设计，不以组件默认样式替代已确定的视觉要求。
具体依赖版本及兼容性须在实施前核实；此选型不代表已完成兼容性或安装包验证。
界面基础能力已于 2026-09-06 确定如下，具体版本仍须核实：

| 能力 | 选型与边界 |
| --- | --- |
| 局部交互状态 | React 自带状态，用于菜单、焦点、弹窗等 |
| 跨组件界面状态 | Zustand，用于当前任务、各任务草稿、面板和流式显示；不成为执行状态权威 |
| Agent 正文 | react-markdown + remark-gfm，支持表格等 Markdown 内容 |
| 代码高亮 | Shiki，按需加载语言，避免每次流式更新重做全部高亮 |
| 代码差异 | 优先验证 react-diff-view；通过样例检查后才锁定，封装为可替换的 DiffViewer |
| 国际化 | i18next + react-i18next，集中管理 en 与 zh-CN 翻译资源 |

真实 Run、审批、历史和文件操作结果仍由 Agent 与共享应用服务负责。Zustand 只维护
界面视图；停止请求发出后显示“正在停止”，收到执行层确认后才显示“已停止”。
不得通过前端持久化再保存第二份规范会话历史。合并高频流式显示更新，明确事件排序、
状态归属和订阅清理，避免每个字符重渲染整个工作台。

Markdown 默认不执行原始 HTML；文件和外部链接经明确的打开逻辑处理。代码块支持复制
和必要的横向滚动；不完整的流式 Markdown 不应导致异常或明显闪烁。审批、工具状态和
成果操作来自结构化数据，不从 Markdown 解析成可执行指令。

差异组件以长文件、多文件、中文路径和大量修改作验证样例，覆盖新增、删除、行号、
分组和折叠；审查基线和用户预存修改归属仍按第 4 节实现。首版不为只读差异展示引入
完整代码编辑器；未来需要直接编辑时再单独评估。

翻译资源使用稳定词条键、插值与数量表达，可按 common、workbench、settings 分类。
主进程菜单与系统对话框文案复用翻译资源；核心保留结构化错误码，界面翻译对应说明并
允许展开原始诊断。界面语言切换不翻译历史、不重新启动任务，遵守第 4 节双语要求。

引擎范围已于 2026-09-06 确定：首版同时支持 **原生 Forge 与 Codex 引擎**。
复用 TUI 现有的两条执行路径与认证边界，使用统一工作台呈现，清楚显示当前引擎和模型。
引擎选择与模型选择是不同概念；不得将 Codex 引擎当作普通 Forge provider 处理。
工具、Skills、插件、审批、上下文与事件按各引擎实际能力呈现，不伪造一致性或偷偷回退。
未配置或不可用时提供明确的配置入口或错误；实现前核实两条路径所需的依赖与打包方式。
跨引擎继续同一会话的规则另行定义并验证，不因支持两种引擎就承诺可迁移运行状态、
provider continuation 或审批。运行中不得直接切换当前执行的引擎。
两条路径分别验收启动、认证、流式输出、取消、错误与历史恢复，并明确不可用的能力。

首批格式、研究范围、搜索接入和内容解析依赖已确定，见第 5 节；继续核实具体版本，
选择插件分发及配置方式，并验证内容解析、打包兼容性与真实搜索服务。
这些决定应考虑现有 TypeScript/Node 复用、文件与进程、窗口生命周期和分发维护。
本阶段输出核心页面、状态与协议说明，不重写 agent。

## 7. 检查与回退

- 聚焦现有 config、tools、core、persistence、CLI session 测试，加上桌面桥接与交互必要回归。
- TypeScript 或 workflow 修改后运行 `CI=true pnpm check`。
- 跨层执行/持久化合约修改后运行 `CI=true pnpm eval:deterministic`。
- 文档修改先运行 `node scripts/build-doc-index.mjs`，再运行 `CI=true pnpm check:docs`。
- packaged resources 或公开制品改变时运行 `CI=true pnpm package:verify`。
- UI 做实际渲染检查；对中英文、长回复、窄窗口、审批与失败状态检查可读性和操作。
- 真实 provider、联网研究结果与离线 fake 结果分开记录；不能用历史报告替代当前检查。

按共享服务抽取、桌面 UI、各能力集成分别提交可审查变更；不要顺手改变 CLI 默认行为。
若必须迁移存储，先定义兼容、备份与失败恢复，禁止覆盖无法迁移的旧记录。
移除桌面入口应仍可使用原 TUI 与原始文件；失败或取消不意味着文件修改已回滚。
