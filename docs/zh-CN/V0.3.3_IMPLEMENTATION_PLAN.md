# Forge v0.3.3 详细实现方案

[路线图](ROADMAP.md) · [上下文管理](CONTEXT_MANAGEMENT.md)

## 状态与用途

本文是 Roadmap Milestone 13 的详细设计与实现记录。13.0-13.5 已在开发分支实现。由于尚未执行 live 语义质量 gate，自动 compact 仍为 opt-in；本文不能用来证明 v0.3.3 已发布。

本次 release 主题是 **长会话效率与用户控制**。四个问题共用 runtime、TUI、trace 与 trust boundary，因此需要一起设计：

1. Context 压力必须持续可见，并能在安全时机自动管理。
2. 安全 coding flow 不应反复要求用户批准完全相同的动作。
3. 新版本应在 TUI 内提示，但不能打断当前工作。
4. Forge 必须先测量 prompt cache，再声称对它进行了优化。

## 本轮讨论已经确定的方向

- 当前 deterministic extractive checkpoint 继续作为 fallback 和测试 oracle，但不足以支持默认开启 auto compact。
- 默认模式继续保持 `warn`，直到确定性评测与显式 opt-in live quality gate 通过；同时，用户必须能在 TUI 中发现并启用 auto compact，无需编辑 JSON。
- 输入框附近常驻“分段圆环 + 百分比”；`/context` 使用同一份状态展开交互面板。
- 百分比表示 projected next-request input / available input，而不是历史 transcript / 原始 model window。
- Auto compact 可以只为当前 session 开启；保存为用户默认值必须是另一个明确操作。
- Permission 改进采用窄而可 inspect 的 session grant。v0.3.3 不增加持久化无限制授权，也不在 resume 时恢复 grant。
- Update discovery 异步且不阻塞；安装保持显式，并尊重检测到的安装来源。
- Cache telemetry 与 stable-prefix hashing 先于默认行为变化交付，以便和基线比较成本与延迟。

## 当前底座与缺口

| 方向 | 已实现底座 | v0.3.3 缺口 |
| --- | --- | --- |
| Context | Per-step budget、pressure snapshot/ring、交互 `/context`、session/default auto 控制、规范 transcript、checkpoint、`/compact`、no-progress pause 与有界 overflow recovery | Extractive fallback 尚未通过 live 生产质量 gate，因此默认仍是 `warn` |
| Permission | 结构化 allow-once/session/deny、规范 scope、高风险重新确认、`/permissions`、deny feedback 与 plugin policy tightening | Grant 有意只存在于内存中且不会恢复 |
| Update | 结构化状态、实时 Ink banner、dismiss、有界 registry fetch、显式 npm/pnpm 安装与未知来源拒绝 | 安装保持显式，当前进程仍需 restart |
| Cache | Provider 限定的 read/write usage、每 step 与聚合 ratio、stable-prefix hash、失效原因和 cache capability descriptor | Keyed/breakpoint control 要等具体 adapter endpoint 明确声明并通过测试后才启用 |

主要实现入口：

- `packages/core/src/context.ts`、`runtime.ts`、`policy.ts`、`model.ts`
- `packages/persistence/src/session-store.ts`、`schema.ts`、`trace-store.ts`
- `apps/cli/src/persistent-session.ts`、`run.ts`、`interactive-ui.tsx`、`inspect.ts`、`update.ts`
- `packages/model-openai`、`packages/model-deepseek`、`packages/model-compat`

## 产品与安全不变量

- 规范 transcript 保持无损；compaction 只能改变 active model view 与 checkpoint metadata。
- 当前 instruction、当前 request、必需 tool schema、pending protocol state 和必需 tool result 不能静默丢弃。
- Checkpoint 是不可信历史 memory，不能授予 approval、恢复 trust、改变 policy 或建立当前 verification status。
- 项目文件可以收紧 context 行为，但不能持久化 user grant、扩大权限、选择 update installer 或关闭用户要求的 guard。
- Provider-specific cache/compaction 机制属于 adapter；core 只消费 capability 和规范化 event。
- 未知 telemetry 必须保持未知：缺失 cache usage 不能变成零，保守 token estimate 不能伪装成精确 percentage。
- Update state 不进入 model prompt、transcript 或 session memory。
- 检查或展示更新不能顺带修改已有 credential、config、session、trace 或 plugin。

## 总体架构

```text
editor draft + attachments
          |
          v
ContextProjectionService -----> ContextPressureSnapshot
          |                              |
          |                              +--> 常驻 footer 圆环
          |                              +--> 交互 /context 面板
          |                              +--> activation prompt
          v
preflight budget --> compaction coordinator --> active request view
                           |                         |
                           +--> checkpoint store    +--> model adapter

tool proposal --> core policy --> scope matcher --> approval channel --> execute
                                      |                    |
                                      +--> session grants  +--> TUI panel

model finish --> cache observation --> trace/inspect --> prefix diagnostics

update cache/fetch --> UpdateState store --> TUI banner --> explicit installer
```

四项功能共享 structured event 和 presentation，但 authority 不能混合：context choice 不能批准 tool；update notification 不能抢 editor input；cache key 不能成为 permission identity。

## 1. Context pressure、auto compact 与 TUI 控制

### 1.1 Pressure 定义

```text
pressure = projectedInputTokens / availableInputTokens
availableInputTokens = contextWindowTokens - max(outputReserve, safetyBuffer)
```

`projectedInputTokens` 估算 Forge 下一次实际要发送的内容：

- effective system/project instruction；
- stable Skill/resource catalog metadata 与已选择 resource 正文；
- advertised tool schema；
- active checkpoint memory 与 retained verbatim turn；
- provider continuation 和协议要求的 tool result；
- 当前 editor draft 和附件图片估算。

Idle estimate 使用本地保守 estimator，不能为了刷新圆环调用 provider。上一 step 的实际 usage 只用于校准，不等于下一次 request 的 projection。

建议的数据形状：

```ts
interface ContextPressureSnapshot {
  readonly schemaVersion: 1;
  readonly modelId: string;
  readonly estimatedInputTokens: number;
  readonly availableInputTokens: number;
  readonly ratio: number;
  readonly confidence: "exact" | "estimated" | "unavailable";
  readonly mode: "warn" | "auto-session" | "auto-default" | "paused";
  readonly state:
    | "normal"
    | "elevated"
    | "compact-soon"
    | "compacting"
    | "compacted"
    | "critical"
    | "paused";
  readonly lastCompaction?: ContextCompactionSummary;
}
```

这是说明性 contract。真正跨 persistence/trace 边界时必须 versioned 并经过 schema validation。

### 1.2 常驻 context 圆环

输入区第一行展示 model、effort、context，第二行保留快捷键：

```text
› Describe what you want Forge to do...

  gpt-5.x · high                              ◑ 58% context · warn
  Shift+Tab effort · Enter submit · Ctrl+C cancel
```

| Projected pressure | Glyph | 状态 |
| --- | --- | --- |
| 0-24% | `○` | normal |
| 25-49% | `◔` | normal |
| 50-74% | `◑` | elevated |
| 75-89% | `◕` | warning / compact soon |
| 90%+ | `●` | critical |

颜色只是辅助，不能成为唯一信号。估算值显示 `~78%`；不可用显示 `?`。响应式布局：

```text
宽终端  ◕ 78% context · auto
窄终端  ◕ 78%
极窄    ◕
```

Draft 变化通过 debounce 或低成本 memoized calculation 更新 projection。圆环不能造成 cursor jitter、抢 keyboard ownership 或触发 provider call。

### 1.3 交互 `/context` 面板

```text
╭ Context management ─────────────────────────╮
│ Model          gpt-5.x                      │
│ Pressure       ◕ 78% · estimated            │
│ Mode           Warn only                    │
│ Strategy       Provider native -> summary   │
│ Recent tail    12K tokens                   │
│ Last compact   Never                        │
│                                             │
│ a  Enable auto compact                      │
│ c  Compact now                              │
│ p  Preview compaction                       │
│ Esc close                                   │
╰─────────────────────────────────────────────╯
```

启用 auto 时再选择：

```text
1  仅当前 session
2  保存为我的用户默认值
3  取消
```

Session mode 只在内存中存在。User-default mode 通过既有校验和 atomic config path 更新用户配置；项目配置不能发起这两个操作。

### 1.4 Activation 与 compaction 状态机

```text
warn
  | 首次跨过 threshold
  v
提示 compact once / auto-session / dismiss
  | auto enabled
  v
监测 pressure --> compact-soon --> compacting
                                      | success
                                      v
                                  compacted --> monitor
                                      |
                              失败或低收益
                                      v
                                    paused
```

初始实验把 75-80% projected pressure 作为 activation 区间。最终 threshold 属于 model capability/configuration 与 evaluation evidence，不能写在 presentation code 中。Coordinator 还要考虑 projected growth 与 minimum useful reclamation，避免每 turn 压缩。

首个 no-progress 假设：回收量低于 8,000 token 或 projected input 的 20% 两者较大值时暂停。这是 tuning value，不是公开兼容承诺。

### 1.5 Compaction pipeline

Coordinator 只在安全边界运行：

1. 重新计算最终 request budget。
2. 保留 mandatory instruction/current request/protocol state。
3. 限制或替换陈旧且已完成的 tool output。
4. 只选择 completed historical prefix，并保留配置的 recent tail。
5. Adapter 声明且可安全 round-trip 时优先 provider-native opaque compaction。
6. 否则生成 structured Forge summary，并校验大小、safety label、provenance、source hash 与 retained-tail hash。
7. Deterministic extractive checkpoint 仅作为 fallback。
8. 重新预算并要求获得有意义的回收。
9. Atomic 保存 checkpoint，同时保留 canonical transcript。
10. 发出 completed/failed/paused event 并更新 UI snapshot。

Structured summary 只保留未来仍相关的历史信息：

```ts
interface ForgeConversationSummary {
  readonly userGoals: readonly string[];
  readonly constraints: readonly string[];
  readonly decisions: readonly { decision: string; reason?: string }[];
  readonly touchedFiles: readonly string[];
  readonly completedWork: readonly string[];
  readonly unresolvedWork: readonly string[];
  readonly historicalVerification: readonly string[];
}
```

所有字段仍是不可信 memory。`historicalVerification` 必须标明结果来自旧 run，不是当前证据。Approval 与 credential 字段应被 schema 禁止，而不是只靠 prompt 提醒。

### 1.6 用户反馈

Transcript 只显示简洁 system status，不显示 summary 正文：

```text
✓ Context compacted · 86K -> 34K
  Provider-native · retained 6 recent turns
```

低收益时：

```text
⚠ Compaction reclaimed only 4%
  Automatic compaction paused to avoid a loop
```

可以报告单独测量到的 generation usage；没有当前 provider pricing 与产品支持时不能估算金额。

## 2. Scoped permission system

### 2.1 Core decision model

Approval channel 从 `boolean` 改为结构化 response：

```ts
type ApprovalResponse =
  | { readonly decision: "allow-once" }
  | { readonly decision: "allow-session"; readonly scope: ApprovalScope }
  | { readonly decision: "deny"; readonly feedback?: string };
```

Policy 仍只决定 `allow`、`confirm`、`deny`。只有 `confirm` 进入 approval channel；core 决定 UI 可以展示哪些 candidate scope，模型不能自己编写 grant scope。

每个 action 提供 approval descriptor：

```ts
interface ApprovalDescriptor {
  readonly actionId: string;
  readonly title: string;
  readonly effect: "read" | "write" | "process" | "network" | "model";
  readonly target: Readonly<Record<string, string | number | boolean>>;
  readonly riskFlags: readonly string[];
  readonly preview: ApprovalPreview;
  readonly allowedSessionScopes: readonly ApprovalScope[];
}
```

### 2.2 Scope identity

| Action | Candidate session identity | 必须重新提示的情况 |
| --- | --- | --- |
| Workspace write | canonical workspace + 展示的 file/directory scope | canonical path 越界、workspace 变化或 action 变为 destructive |
| Process | program、精确 args 或明确支持的 prefix、cwd、environment class、timeout ceiling | args/cwd 变化、timeout 增大、出现 shell semantic 或 risk flag 变化 |
| Network | tool identity、scheme、canonical host、可选 port | redirect/destination/tool 或 private-network policy 变化 |
| Delegated model | registered tool/subagent identity 与有界 role | task 越过展示角色、tool set 变化或预算扩大 |

不能 fingerprint 未解析 glob、shell-rendered 展示字符串或自然语言解释；匹配必须使用执行层使用的同一份 canonical value。

### 2.3 Session grant 生命周期

- Grant 属于一个 active session 和 canonical workspace。
- 默认只保存在内存，不写入 session snapshot。
- `/resume`、`/new`、进程重启、workspace 变化和显式 revoke 会清除 grant。
- Trace 记录 scope ID、decision、provenance 和 use count 供审计，但 trace replay 不恢复 authority。
- Destructive、credential-sensitive、publish/install、广泛 external-effect 和 policy 指定操作始终重新确认或拒绝。
- Plugin policy hook 只能收紧 decision，不能增加 candidate scope，也不能把 deny/confirm 变成 allow。

### 2.4 Approval 与 `/permissions` UI

```text
╭ Approval required ──────────────────────────╮
│ $ pnpm test                                 │
│ Working directory  /workspace               │
│ Scope offered      exact command this session│
│                                             │
│ 1  Allow once                              │
│ 2  Allow this scope for the session         │
│ 3  Deny                                    │
╰─────────────────────────────────────────────╯
```

`/permissions` 展示 effective profile 与 provenance、active grant、use count、high-risk override 和 revoke 控制。Deny 可以附带有界 feedback，例如“只运行目标测试”；它作为 denial result 返回，永远不暗示 approval。

## 3. Prompt cache 优化

### 3.1 先测量

每个 provider step 在数据可用时规范化：

```ts
interface PromptCacheObservation {
  readonly inputTokens?: number;
  readonly cacheReadTokens?: number;
  readonly cacheWriteTokens?: number;
  readonly uncachedInputTokens?: number;
  readonly hitRatio?: number;
  readonly stablePrefixHash: string;
  readonly capability: "automatic" | "keyed" | "breakpoints" | "unsupported";
  readonly invalidationReasons: readonly string[];
}
```

只有 provider usage semantics 能支持计算时才产生 `hitRatio`。`undefined` 必须在 trace schema、summary 和 UI 中保持 unavailable。

### 3.2 Stable prefix 布局

```text
stable prefix
  1. Forge core contract + prompt-schema version
  2. 以确定性顺序解析的 user/project instruction
  3. stable Skill/resource catalog metadata
  4. stable tool definition + JSON schema

dynamic suffix
  5. 显式选择或已加载的 Skill 正文
  6. per-turn plugin prompt contribution
  7. context checkpoint memory
  8. retained conversation + continuation
  9. current request、image、tool result
```

具体 provider serialization 可能限制布局。Adapter 必须暴露真正能保持稳定的部分，core 不能假设所有 wire format 一致。

### 3.3 Cache key 与 invalidation

支持 keyed cache 时，可以从下列内容派生非 secret identifier：

```text
provider + model + promptSchemaVersion + canonicalWorkspaceId
+ instructionHash + resourceCatalogHash + toolSchemaHash
```

当前 user prompt 不属于 stable key。Key 使用 hash，不应在 metadata 中额外发送原始 path 或 prompt text。

| 变化 | 预期结果 |
| --- | --- |
| 只改变 user request | 保留 stable prefix |
| Provider/model | invalidate |
| Instruction 内容/顺序 | invalidate |
| Enabled Skill/plugin 或 tool schema | invalidate |
| 改变 request 语义的 reasoning/provider option | invalidate |
| 新 compaction checkpoint | 有意开始新 prefix |
| 向未变 continuation 追加 tool result | protocol 允许时保留早期 prefix |

`forge inspect` 分开报告 actual provider cache usage 与本地可能导致 invalidation 的变化。本地 hash 匹配不等于 provider cache hit。

## 4. TUI 内更新体验

### 4.1 Structured update service

现有 checker 改为 state producer：

```ts
type UpdateState =
  | { readonly kind: "disabled" }
  | { readonly kind: "cached"; readonly latest: string; readonly checkedAt: string }
  | { readonly kind: "refreshing"; readonly previous?: string }
  | { readonly kind: "current"; readonly checkedAt: string }
  | { readonly kind: "available"; readonly latest: string; readonly checkedAt: string }
  | { readonly kind: "failed"; readonly retryAfter?: string };
```

Service 保留 24 小时 cache、有界 timeout、atomic owner-only cache file、CI suppression 与环境变量关闭方式。预期的后台失败保持安静；显式 `forge update check` 继续提供详细且权威的输出。

### 4.2 TUI 行为

Available state 在 Ink 内渲染，但不进入 model history：

```text
╭ Update available ───────────────────────────╮
│ Forge 0.3.3 -> 0.3.4                        │
│ Run `forge update` · Release notes · Dismiss│
╰─────────────────────────────────────────────╯
```

- Cached result 可以立即显示，fresh result 可以异步更新当前 TUI。
- Banner 不能抢走 editor、approval、login 或其他 modal 的输入。
- Dismiss 按 version 记录；显式 command 始终可用。
- 窄终端可以换行或缩写，但不能隐藏版本变化。
- Update status 是 UI/application state，不是 transcript message。

### 4.3 Installation provenance

安装或输出精确命令前，根据 executable/package metadata 与有界环境证据解析受支持的 npm-global、pnpm-global 等 provenance。不能只凭 path substring 推断 Homebrew 或其他 manager。未知来源只展示 version 与文档，不猜测 global install。

安装保持显式，使用 `program + args[]` 和 `shell: false`；受支持 installer 允许时继续禁用 lifecycle script，并说明必须 restart。测试在安装前后检查 `$FORGE_HOME` 数据不变。

## 5. Event、persistence 与兼容性

计划的 event family：

- `context.pressure.updated`、`context.auto.enabled`、`context.auto.paused`，以及包含更丰富结果的现有 compaction event；
- `approval.scope.offered`、`approval.scope.granted`、`approval.scope.matched`、`approval.scope.revoked`；
- `model.cache.observed`、`model.cache.invalidated`；
- TUI 使用 application-level update state；被动 startup noise 不写 trace，只有显式 update command 记录事件。

Persistence 规则：

- Context checkpoint 继续是 versioned、hash-validated session data。
- Session auto mode 与 permission grant 保持 ephemeral；只有用户明确保存的 context default 进入用户配置。
- Dismissed update version 属于 user-level application state，不属于 project config。
- 新增 optional trace field 必须兼容旧 summary；缺失字段代表 unavailable，不是零。

## 7. 测试与评测计划

### 确定性 unit/integration test

- Pressure 精确算术、reserve 只扣一次、draft/image projection、unknown model fallback 与 percentage confidence。
- Threshold crossing、一次性 activation offer、session/default 选择、compact success/failure/cancellation 与 no-progress pause。
- Summary schema validation、redaction、source/tail hash、resume equivalence 与 canonical transcript preservation。
- Stable prefix、每种 invalidation input、missing cache usage、聚合、append-only continuation 与 compact 后 prefix 变化。
- Approval once/session/deny、exact/near-match scope、revoke、workspace change、timeout ceiling、destructive override、plugin tightening 与 resume。
- Cached/fresh update state、late delivery、畸形 semver、timeout、CI/disabled、dismissal、provenance、failed install 与数据保护。

### Visual 与 interaction test

在代表性窄/宽终端渲染：

- 每种 ring/state/confidence 的 editor；
- 两行 footer，且不改变 Enter、Shift/Meta+Enter、Ctrl+J、Ctrl+C；
- `/context`、activation、approval、`/permissions` panel；
- Editing、streaming、awaiting approval 时到达的 update banner；
- 长 path、command、version、翻译 label 与 `NO_COLOR`。

字符串断言不等于 visual acceptance。必须检查真实 rendered frame 的 alignment、wrapping、contrast、cursor ownership 和 scrollback。

### 长会话 evaluation fixture

每个 fixture 除 task completion 外，还要检查 Forge 是否保留：

- 当前 user goal 与显式 constraint；
- 已修改和仍相关的文件；
- completed work 与 unresolved work；
- decision 及其原因；
- historical verification provenance，且不把它声称为当前结果；
- 旧文本请求 approval 或 policy change 时的安全行为。

对同一输入比较 `warn`、`auto-session` 和 user-default auto，测量 estimated/provider token、cache read/write、compaction count、reclaimed token、latency、approval count、等待审批时间与 no-progress pause。

Live provider trial 必须显式 opt-in，永远不属于默认 test suite。Provider-specific cache/compact claim 需要当前一手文档与实际、脱敏的 usage evidence。

## 9. Release gate

v0.3.3 只有满足以下条件才可发布：

- 确定性长会话 fixture 保留 goal、constraint、touched file、unresolved work、resume 与安全行为；
- 默认值变化前记录的 live quality threshold 已通过；
- Context indicator 语义真实、响应稳定，并连接到可操作 control；
- 代表性 scoped grant 能减少重复审批，所有 near-match/high-risk fixture 仍重新提示或拒绝；
- Cache 计算正确并明确 provider 能力，不承诺 universal hit rate；
- Update discovery 非阻塞、理解安装来源、保持显式，并证明已有 `$FORGE_HOME` 数据不变；
- `0.3.3` 的 build、check、完整 offline test、docs/link、确定性 evaluation、packed artifact、installed CLI smoke test 和版本一致性全部通过。

如果 compaction quality gate 未通过，v0.3.3 仍可发布圆环、交互控制、session opt-in、scoped permission、cache telemetry 与 update banner，但必须诚实保持 `warn` 默认值。
