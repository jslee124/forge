## 范围与当前事实

当前桌面端已实现「启动自动检查 → 用户点击下载 → 校验 → 打开 DMG → 手动替换应用」。不提供自动覆盖应用或重启安装，不改变现有签名配置。发布和手动替换已安装应用仍是独立操作。

## 界面与状态

启动完成后后台检查，不能阻塞窗口或任务；默认不自动下载。设置页增加版本与更新区，展示当前完整桌面构建版本、更新渠道、上次成功检查时间、检查结果、更新说明和手动检查入口。自动检查可关闭，偏好持久化；开发模式及自动化测试默认不联网。

| 状态 | 设置旁入口 | 行为 |
| --- | --- | --- |
| 未检查／检查中／已是最新 | 无按钮 | 设置页显示状态；检查失败不能显示已是最新 |
| 有新版本 | 下载更新 | 显示目标版本；点击才开始下载 |
| 下载中 | 下载中…及进度 | 可取消；未知总长度使用不定进度 |
| 校验中 | 正在校验… | 校验通过前不可打开 |
| 已校验 | 打开安装包 | 打开已验证 DMG，不退出 Forge |
| 检查／下载／校验失败 | 下载失败时显示重试 | 设置中显示具体错误和重试；自动检查失败不弹模态框 |

入口位于左侧栏底部设置按钮旁。收起侧栏时使用带完整 tooltip 与无障碍名称的图标，保持设置入口可用；深浅色、中英文和窄窗口均须验收。重试下载必须重新校验；取消后保留版本提示。

打开 DMG 后说明：先保存工作并退出旧 Forge，再拖入 Applications 手动替换。打开安装包本身不会关闭应用，现有草稿与运行中任务的退出保护继续生效。不得把「下载更新」标作「安装更新」或「重启安装」。

## 发布与版本契约

- 使用固定官方 GitHub 仓库的 Release API，仅识别 `desktop-<semver>` 桌面标签，排除 CLI 的 `v*` 标签、草稿和不合法版本。按语义版本比较，不按发布日期、字符串排序或 GitHub latest 单一结果判断；列表需分页并设置边界，未查完不能误报最新。
- 稳定版默认稳定渠道；预览版默认预览渠道，预览渠道也接受更高版本的稳定版。设置可选稳定／预览，切换后重新检查，不自动降级。
- 当前应用包版本 `0.3.4` 不足以辨识 `desktop-0.3.4-preview.1`。实现前须加入打包时生成的桌面构建身份（完整语义版本、渠道），与发布标签一致；旧包缺失身份时明确说明，不能猜测预览序号。旧版本不会因新增文档自动获得检测能力，首次仍需手动安装带此功能的版本。
- 按运行应用架构选择 arm64/x64 DMG（含 Rosetta 的 x64 进程）；不隐式跨架构迁移。匹配明确的 `forge-desktop-<package-version>-<arch>.dmg` 和同一 Release 的 `SHA256SUMS`；发布约定必须记录完整构建身份与文件名版本的映射。
- 候选版本必须具有对应架构文件及唯一、合法的校验值；缺失时说明发布产物不完整，不把不兼容候选当作可下载更新。更新说明显示为文本或安全链接，不执行远端 HTML。

## 实现边界

更新检查、下载、校验与打开文件均在 Electron 主进程的独立服务中完成。preload 仅暴露检查、下载、取消、打开与状态订阅的窄 IPC；renderer 不传任意下载 URL 或本地路径，不接触文件系统。设置偏好不进入模型上下文，不使用提供商凭据。

只允许固定官方源的 HTTPS 元数据及经过校验的 GitHub 资产重定向，禁止任意协议、任意主机和路径穿越。限定超时、响应大小、文件大小、重定向次数和重试；并发请求去重，支持取消，处理限流、代理／离线、磁盘不足和进程退出。

下载到应用管理的临时目录，使用临时文件；完成后计算 SHA-256，与同 Release 的 SHA256SUMS 比较，再原子移动为可打开文件。校验失败删除临时文件。重启后如复用缓存须重新校验；打开前再次确认受管文件与校验状态。缓存按版本清理，不删除用户手动保存的文件。

SHA-256 用于完整性检测，不等于 Apple 签名、公证或独立来源认证。未签名应用的系统提示仍可能出现，不自动移除 quarantine、不绕过 Gatekeeper。未来取得证书后可评估 electron-updater，复用界面状态；本轮不接入自动替换链路。

## 构建与缓存契约

发布构建必须设置 `FORGE_DESKTOP_BUILD_TAG=desktop-<完整语义版本>`，打包命令拒绝缺少身份的构建。完整版本嵌入主进程，major.minor.patch 必须与包版本一致；开发构建未设置时明确显示身份缺失。验收使用的 `desktop-0.3.4-preview.2` 现已作为预览版标签发布。

`release-contract.mjs` 在两种架构的 DMG/ZIP 全部生成后输出 `SHA256SUMS` 和 `desktop-build.json`。另获发布授权后，才将这两个文件及四个安装产物一起上传到匹配的桌面标签。更新检查先验证校验清单，再提供下载；下载前再次读取清单，如摘要变化则要求重新检查。

主进程使用独立、非持久化的 Chromium 网络会话，不携带凭据；每次跳转发送前验证目标。参见 [Electron 网络文档](https://www.electronjs.org/docs/latest/api/net)。最多检查 10 页、每页 100 条，检查限时 30 秒；每页元数据限 4 MiB，校验清单限 1 MiB，安装文件限 2 GiB，下载限时 15 分钟，重定向最多四次。仅用户主动重试。Chromium 使用系统代理设置，失败明确显示，不自动绕过代理。

偏好位于 Electron userData/desktop-updates，不进入 Forge 会话。安装器使用私有会话目录，正常退出时清理，重启不复用。初始化清理超过 24 小时的遗留会话目录（每次最多检查 1,000 项）；重新检查时删除当前缓存目录内上一版本的安装器，不触及用户另存的文件。上次成功检查时间只描述本次应用会话。
